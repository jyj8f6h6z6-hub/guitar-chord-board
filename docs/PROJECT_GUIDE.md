**## 2. 平常修改網站的流程**

**### 第一步：開啟專案**

使用 VS Code 開啟：

\`\`\`text
D:\guitar-chord-board
\`\`\`

VS Code 終端機應顯示類似：

\`\`\`text
PS D:\guitar-chord-board>
\`\`\`

若不在正確資料夾，執行：

\`\`\`powershell
cd D:\guitar-chord-board
\`\`\`

**### 第二步：查看目前狀態**

\`\`\`bash
git status
\`\`\`

修改前若顯示：

\`\`\`text
nothing to commit, working tree clean
\`\`\`

代表目前沒有尚未提交的修改。

若出現修改中的檔案，先確認它們是不是上次尚未完成的工作，不要直接覆蓋。

**### 第三步：啟動本機網站**

\`\`\`bash
npm run dev
\`\`\`

瀏覽器通常會開啟：

\`\`\`text
http\://localhost:5173
\`\`\`

停止本機網站時，在終端機按：

\`\`\`text
Ctrl + C
\`\`\`

**### 第四步：修改程式**

修改完成後，先儲存所有檔案。

VS Code 分頁旁若有小圓點，代表檔案尚未儲存。

也可以使用：

\`\`\`text
Ctrl + S
\`\`\`

儲存目前檔案。

**### 第五步：檢查程式**

先停止正在執行的 \`npm run dev\`，再依序執行：

\`\`\`bash
npm run typecheck
npm run build
\`\`\`

用途：

\- \`npm run typecheck\`：檢查 TypeScript 型別。
\- \`npm run build\`：建立正式版網站並再次檢查程式。
\- 成功後會產生 \`dist\` 資料夾。

兩個指令都成功後，再執行：

\`\`\`bash
npm run dev
\`\`\`

使用瀏覽器確認畫面與操作正常。

**### 第六步：查看這次修改**

\`\`\`bash
git status
\`\`\`

確認只有預期修改的檔案。

若只是修改文件，建議只加入該文件：

\`\`\`bash
git add docs/PROJECT\_GUIDE.md
\`\`\`

若是修改網站程式，建議只加入 \`src\`：

\`\`\`bash
git add src
\`\`\`

不要在有 \`.bak\`、\`.patch\`、臨時 \`.cjs\` 工具時直接使用：

\`\`\`text
git add .
\`\`\`

以免把臨時檔案一起上傳。

**### 第七步：提交到 GitHub**

例如修改網站程式：

\`\`\`bash
git add src
git status
git commit -m "描述這次修改"
git push
\`\`\`

例如更新本文件：

\`\`\`bash
git add docs/PROJECT\_GUIDE.md
git status
git commit -m "更新專案操作手冊"
git push
\`\`\`

**## 5. 常見 Git 訊息**

**### \`nothing to commit\`**

代表目前沒有新的修改可以提交。

可能原因：

\- 檔案沒有修改。
\- 檔案尚未儲存。
\- 修改已經提交。
\- 修改後又改回原本內容。

先確認檔案已儲存，再執行：

\`\`\`bash
git status
\`\`\`

**### \`Everything up-to-date\`**

代表本機沒有新的 commit 需要推送。

**### \`LF will be replaced by CRLF\`**

Windows 上可能看到：

\`\`\`text
warning: LF will be replaced by CRLF
\`\`\`

這是換行格式提醒，通常不是程式錯誤，也不代表 push 失敗。

**### Push 被拒絕**

不要使用：

\`\`\`text
git push --force
\`\`\`

先執行：

\`\`\`bash
git pull --rebase
\`\`\`

沒有衝突時再執行：

\`\`\`bash
git push
\`\`\`

若出現 conflict，先停止操作並確認衝突檔案，不要任意刪除內容。

**### \`patch does not apply\`**

代表 patch 建立時的檔案內容，與目前本機檔案不完全一致。

不要強制套用。先確認：

\`\`\`bash
git status
\`\`\`

並改用完整檔案覆蓋或專用修正工具。

**## 7. 目前網站的三個功能區**

網站目前有三個功能區：

\`\`\`text
單一和弦查詢
① 建立和弦編排
② 精簡總覽與移調
\`\`\`

三個模式由：

\`\`\`text
src/App.tsx
\`\`\`

統一管理與切換。

**### 單一和弦查詢**

用途：

\- 使用選單組合和弦，不需要切換中文或英文輸入法。
\- 查看聽感描述、組成音、吉他指法與所有可用把位。

選單分為：

\`\`\`text
根音
升降記號
和弦類型
\`\`\`

例如：

\`\`\`text
根音：C
升降記號：♯
和弦類型：m7
\`\`\`

會組合成：

\`\`\`text
C#m7
\`\`\`

**### ① 建立和弦編排**

用途：

\- 以「待選區」固定顯示 \`C、D、E、F、G、A、B\`。
\- 點擊待選和弦即可加入，或拖曳到「和弦編排區」的指定位置。
\- 待選區不會因加入和弦而減少，因此可重複加入相同和弦。
\- 編排區內的和弦可拖曳重新排序。
\- 將編排區內的和弦拖出編排區並放開即可移除；觸控裝置另有 \`×\` 按鈕。
\- 點擊編排區中的某一個和弦時，才顯示完整按法與 12 種同根音類型。
\- 選擇類型時，只替換目前點選的那一個和弦。
\- 點選編排區中的和弦後，可使用「升降記號」選單切換自然音、♯ 或 ♭，並保留原本和弦類型。
\- 可替每個編排項目選擇不同把位。

**### ② 精簡總覽與移調**

用途：

\- 直接顯示建立和弦編排「和弦編排區」目前的結果。
\- 保留建立和弦編排的順序、重複項目、類型與選定把位。
\- 不顯示未點選的其他候選類型。
\- 提供「♫ 原調」與「⇄ 目標調」選單。
\- 可先預覽移調，不立即修改建立和弦編排。
\- 確認後可將移調結果套用到建立和弦編排的和弦編排區。
\- 可恢復原調。

精簡總覽與移調不是另一份獨立資料，而是建立和弦編排編排結果的同步總覽。

\| \`sus2\` | 掛二和弦     | 明亮、空靈、空間感   |
\| \`m7b5\` | 半減七和弦   | 酸楚、憂鬱、過渡張力 |

**## 12. 建立和弦編排的檔案與資料流**

主要元件：

\`\`\`text
src/components/search/SongChordMode.tsx
\`\`\`

拖曳套件：

\`\`\`text
@dnd-kit/core
@dnd-kit/sortable
@dnd-kit/utilities
\`\`\`

**### 編排資料**

建立和弦編排使用：

\`\`\`ts
interface SongChordItem {
  id: string;
  symbol: string;
}
\`\`\`

範例：

\`\`\`ts
[
  { id: "唯一-id-1", symbol: "C" },
  { id: "唯一-id-2", symbol: "G" },
  { id: "唯一-id-3", symbol: "C" },
];
\`\`\`

獨立 ID 可確保兩個相同的 \`C\` 仍能分別移動、修改類型與選擇把位。

**### 待選區**

固定顯示：

\`\`\`text
C D E F G A B
\`\`\`

操作方式：

\- 點擊：加入編排區最後面。
\- 拖曳：插入編排區的指定位置。
\- 待選和弦不會減少，可重複加入。
\- 開啟「移除重複和弦」時，已存在的相同 symbol 不會再次加入。

**### 和弦編排區**

支援：

\- 第一個和弦置中顯示。
\- 拖曳到另一個和弦前方、後方或兩者中間。
\- 拖曳既有和弦重新排序。
\- 拖出編排區並放開即可移除。
\- 觸控裝置顯示 \`×\` 作為移除備用操作。
\- 剩餘項目會自動重新排列。

拖出移除依賴：

\`\`\`ts
collisionDetection = { pointerWithin };
\`\`\`

若改回 \`closestCenter\`，滑鼠離開編排區後仍可能命中最近的項目，導致無法判斷 \`event.over === null\`。

**## 16. 和弦資料分成三個主要檔案**

\`\`\`text
src/data
├── chordShapes.ts
├── chordTypes.ts
└── generatedChordShapes.ts
\`\`\`

三個檔案都要保留。

它們不是重複檔案。

**### \`src/data/chordShapes.ts\`**

負責：

\- 保存人工整理的開放和弦與特殊按法。
\- 整合人工按法與自動產生按法。
\- 查詢某個和弦的全部按法。
\- 排序多個把位。
\- 建立快速查詢表。
\- 驗證資料格式。
\- 提供把位名稱。
\- 提供統計資料。

這是和弦指法資料的主要入口。

其他元件通常呼叫：

\`\`\`ts
findChordShapes(symbol);
\`\`\`

而不是直接讀取陣列。

**### \`src/data/chordTypes.ts\`**

負責：

\- 單一和弦查詢的根音選單。
\- 單一和弦查詢的升降記號選單。
\- 12 種和弦類型。
\- 中文名稱。
\- 聽感描述。
\- 組合和弦名稱的 \`buildChordSymbol()\`。
\- 建立和弦編排右側的 12 種候選類型。

修改類型名稱或聽感描述時，主要修改這個檔案。

**### \`src/data/generatedChordShapes.ts\`**

負責使用模板自動建立可移動按法。

目前支援：

\- 低音 E 弦根音按法。
\- A 弦根音按法。
\- 第 1 格至第 11 格的常用把位。
\- 12 種和弦類型。
\- 自動建立 \`baseFret\`。
\- 自動建立橫按資料。
\- 自動建立把位名稱。
\- 避免加入與現有手寫指法完全相同的資料。

第 12 格通常與空弦音高重複，因此自動資料只建立第 1 至第 11 格。

**## 17. 手寫按法與自動產生按法**

目前和弦按法來源有兩種。

**### 手寫按法**

放在：

\`\`\`text
src/data/chordShapes.ts
\`\`\`

適合：

\- 開放和弦。
\- 初學者簡易按法。
\- 特殊轉位。
\- 不符合一般 E 型或 A 型模板的按法。
\- 想指定特定手指編號的按法。

例如：

\`\`\`text
C 開放位
F 簡易位
Cadd9 開放位
Bm7 簡易位
\`\`\`

**### 自動產生按法**

由：

\`\`\`text
src/data/generatedChordShapes.ts
\`\`\`

使用模板產生。

適合：

\- 封閉和弦。
\- 低音 E 弦根音。
\- A 弦根音。
\- 同一類型沿著指板移動的按法。

例如 C 大三和弦可能包含：

\`\`\`text
開放位
第 3 格・A 弦根音
第 8 格・低音 E 弦根音
\`\`\`

**### 合併規則**

\`\`\`text
人工按法
    +
自動產生按法
    ↓
完全相同的 symbol 與 frets 去除重複
    ↓
findChordShapes()
\`\`\`

排序原則：

1\. \`beginner\` 標籤優先。
2\. 開放位優先。
3\. 較低把位優先。
4\. 難度較低者優先。

因此 \`G#\` 不會只顯示第 11 格 A 弦根音，也可以顯示第 4 格低音 E 弦根音。

**## 18. 和弦按法資料規則**

\`frets\` 順序固定為：

\`\`\`text
低音 E、A、D、G、B、高音 e
\`\`\`

例如：

\`\`\`ts
frets: ["x", 3, 2, 0, 1, 0];
\`\`\`

代表：

\`\`\`text
低音 E：不彈
A：第 3 格
D：第 2 格
G：空弦
B：第 1 格
高音 e：空弦
\`\`\`

數值規則：

\- \`"x"\`：不彈。
\- \`0\`：空弦。
\- 正整數：實際琴格。
\- \`baseFret\`：和弦圖第一格的實際琴格。
\- \`barres\`：橫按資料。
\- \`fingers\`：六條弦的手指編號。
\- \`position: "open"\`：開放位。
\- \`position: "movable"\`：可移動按法。

手指編號：

\`\`\`text
1：食指
2：中指
3：無名指
4：小指
\`\`\`

**### 一筆資料的重要欄位**

\`\`\`ts
{
  id: "唯一識別名稱",
  symbol: "Cmaj7",
  displayName: "C Major 7",
  frets: [...],
  fingers: [...],
  baseFret: 1,
  barres: [...],
  difficulty: 1,
  position: "open",
  variantLabel: "開放位",
  tags: [...]
}
\`\`\`

**### 驗證項目**

啟動時會檢查：

\- \`id\` 不可重複。
\- \`frets\` 必須有六個位置。
\- \`fingers\` 必須有六個位置。
\- 琴格數值必須有效。
\- 橫按弦數範圍必須有效。
\- 橫按琴格必須有效。

新增資料後若網站無法啟動，先查看終端機顯示的資料驗證錯誤。

**## 37. 0.8.0：分數和弦（低音）**

**### 功能**

\- 單一和弦查詢新增「低音」列，可選任何一個音，例如 `C/G`、`G/B`、`Am7/G`。
\- 和弦編排頁選中和弦後，「目前編輯」區新增「低音（分數和弦）」；切換和弦類型時會保留已選的低音。
\- 低音與根音相同時按鈕停用（等於原位和弦）。

**### 按法如何產生**

\- 手寫的分數和弦按法（`chordShapes.ts` 內 `slash` 標籤的資料）永遠排在最前面。
\- 其餘由 `src/services/slashChords.ts` 即時產生並快取，不需要手寫：
  1. 先拿原位和弦的所有按法，把最低音換成指定低音。
  2. 若結果少於 3 種，再直接搜尋可按的指法補上。
\- 每一個產生的按法都會檢查：最低音正確、組成音完整（五度可省略；七和弦、九和弦可省略根音）、不含和弦以外的音、手指寬度不超過 4 格、手指數不超過 4。
\- 最多顯示 5 種，依手指數、橫按、把位高低排序；有空弦的把位優先。
\- 指法（手指編號與橫按）由程式推算，與手寫按法一樣顯示在和弦圖上。

**### 覆蓋範圍**

\- 12 個根音 × 12 種類型 × 11 個低音，共 1584 種組合，其中 1583 種有按法；唯一沒有的是 `F#mM7/Eb`。
\- 驗證方式：逐一檢查每個按法的實際音高（最低音、必要組成音、有無多餘的音），結果全數通過。

**### 修改注意**

\- 想修正某個產生出來的按法太難或不好按，直接在 `HAND_AUTHORED_CHORD_SHAPES` 補一筆手寫的同名分數和弦即可，手寫的會排在最前面。
\- `tonal` 的 `Chord.get` 用來取得組成音；`slashChords.ts` 內的 `MAX_FRET_SPREAD`、`MAX_SHAPES_PER_CHORD` 可調整寬度與顯示數量。

**## 38. 0.9.0：分行編排、歌詞、簡譜風格譜面、演奏模式、歌單**

**## 44. 1.1.0：貼近原譜的簡譜風格譜面**

\- 拍數：每個和弦可設持續幾拍（½、1、1½、2、3、4、6、8，以拍號分子為單位）；每首歌有「預設拍數」，沒個別設定的和弦都用它。譜面欄寬依拍數決定（1 拍約 1.6 個字寬，歌詞比欄寬時自動撐開），沒有歌詞的延音和弦只用欄寬表示，不加符號。
\- 小節線：設了「拍號」與拍數後，整行每個和弦都有拍數時，累積滿一小節就在該和弦後自動畫線。選取和弦後按「｜ 小節線」可取消自動線（記為 `noBar`），也可手動加線（`bar`）。計算在 `src/services/songModel.ts` 的 `autoBarIds`／`effectiveBarIds`。
\- 和弦圖：譜面不再每欄都放圖。三種模式：上方圖例（預設，不重複和弦各一張）、首次出現小圖、不顯示。演奏模式預設首次出現小圖，可循環切換。
\- 節編號：每個段落的第一行（或整首的第一行），如果有 2 節以上歌詞，在每節第一個字左側標「一、二、三、」。
\- 和弦名稱排版：♯♭ 為上標，sus4、7、maj7 等為縮小的下標，m 維持原大小（`src/utils/chordFormat.ts`、`ChordName.tsx`）。
\- 歌曲設定新增：大調／小調、拍號（2/4、3/4、4/4、6/8、12/8、2/2、3/8）、預設拍數。標題顯示為「D 大調 2/4」，列印標題與演奏模式也會帶上。
\- 小節線改成只出現在和弦名稱那一列的細線，不被和弦圖撐高。
\- 匯出檔與分享連結多了 `mode`、`ts`、`beats`（歌曲）與 `beats`、`nobar`（和弦）欄位；舊檔照常可讀。

**## 48. 1.3.0-exp.1：簡譜旋律（試驗版）**

\- 版號 `1.3.0-exp.1` 是「試驗第 1 版」：畫面標題旁顯示 Experimental 1，頁尾顯示完整版號。之後試驗版依序 `1.3.0-exp.2`…，正式版去掉 `-exp.N`（`src/version.ts`）。
\- 旋律：每個和弦可有一段簡譜（`SongItem.melody`）。編排畫面每行下方有「♪ 旋律（簡譜）」：打整行文字，程式依各和弦的拍數自動切到每個和弦（`setLineMelody`／`distributeTokens`）；也有按鈕面板、拍數與字數檢查、這一行的預覽。
\- 語法（`src/services/melody.ts`）：`1`～`7` 音高（首調）、`0` 休止、`-` 延長一拍、`'` 高八度、`,` 低八度、`#` `b` `n` 升降還原（寫在數字前）、`_` 八分、`__` 十六分、`.` 附點、`( )` 連音線（括號內只配一個字）、`|` 只為方便閱讀。全形符號會自動換成半形。音長單位是「拍」，與和弦拍數相同；拍號分母 8 的歌（6/8）1 拍是一個八分音符，不加底線就是八分音符。
\- 顯示：旋律在和弦與歌詞之間。每個音符一欄，欄寬依音長（1 拍 2em，最窄 1.15em）；歌詞一字對一個音，連音線與延長、休止不配字，多出的字接在最後一個音後面。八度點、升降記號、附點、底線（在整數拍斷開）、連音線弧線都畫在同一欄裡。總覽與演奏模式可開關「顯示旋律」（`guitar-chord-board:show-melody`）；和弦圖卡片、不重複和弦兩種總覽不顯示旋律。
\- 轉調：簡譜是首調，旋律數字不變；標題改成「1=D 4/4」（小調歌曲寫關係大調，如 A 小調 → 1=C）。
\- 小節線樣式：選取和弦後，工具列新增「線型」：標準、‖ 雙線、終止線、:‖ 反覆結束，以及「‖: 反覆開始」與「房子」（1.、2.、3.）。全曲最後一個和弦預設畫終止線（可用「取消小節線」關掉）。房子的括線從標記的和弦畫到有線型的和弦或行尾。小節線現在畫在「和弦＋旋律」那一層，不穿過歌詞。
\- 資料：和弦新增 `melody`、`barStyle`、`repeatStart`、`ending`；匯出檔與分享連結的和弦多了 `mel`、`bs`、`rs`、`end`。舊檔照常可讀，旋律文字載入時只保留簡譜語法會用到的字元。
\- 已知限制：旋律文字是跟著和弦走的，把和弦拖到別行時旋律一起移動，但改拍數不會自動重排旋律（編輯畫面會提示拍數不符）；手機窄畫面一個和弦（例如 4 拍）常常獨佔一行。
